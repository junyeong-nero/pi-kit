06 · 선택 근거

왜 pi를 기반으로 구성했는가?

이 과제의 기준 pi에서 활용한 특성 구현 근거
사내 API 연결 provider·baseUrl·모델을 설정으로 지정 config/models.example.json
도구와 피드백 확장 TypeScript 도구 등록·편집 결과 이벤트 extensions/cpp-csharp-lsp-lite/index.ts
Windows 배포 공식 standalone 실행 파일과 리소스 동봉 bin/pi/
필요 기능 추가 배포 폴더를 pi 패키지로 로드 package.json · config/settings.json

근거: 동봉 pi 1.3.0 문서 및 현재 저장소 구현. 제품 간 성능 비교 실험은 수행하지 않음.

선택의 대가: 확장 API 호환성과 Windows 동작은 배포자가 계속 검증해야 한다.

09 · LSP의 필요성

같은 문자열과 같은 심볼은 다르다

// 개념 예시: 동명 멤버 함수
struct Sensor { int read(); };
struct Buffer { int read(); };

Sensor sensor;
Buffer buffer;
sensor.read();  // Sensor::read
buffer.read();  // Buffer::read

문자열 검색: read 후보 수집

선언·호출·주석 등 이름이 나타난 곳을 찾는다.

LSP: 위치와 타입을 기준으로 질문

sensor.read()의 정의와 참조,
타입·서명을 서버에 조회한다.

개념 근거: LSP의 definition · references · hover

이름 검색에 프로젝트의 의미 정보를 더해, 변경 대상을 확인한다.

부록 A · 준비 PC

현재 구성: setup.ps1로 한 번 설정하고 pi로 실행

# 배포 폴더에서 한 번 (관리자 승인)
Set-ExecutionPolicy -Scope Process Bypass
.\setup.ps1
# 이후 새 터미널의 어느 폴더에서나
pi

# 아무것도 바꾸지 않고 필수 파일만 확인
.\setup.ps1 -Check

부록 B · 방산망 실행

압축 해제 → 사내 모델 설정 → setup.ps1 → pi

PS> Expand-Archive .\pi-offline-kit-win-x64.zip -DestinationPath D:\
PS> cd D:\pi-offline-kit
PS> Copy-Item config\models.example.json config\models.json
# config\models.json의 baseUrl / model id를 사내 제공 값으로 편집
PS> setx /M CORP_LLM_API_KEY "<발급받은 API KEY>"   # 관리자 터미널
PS> Set-ExecutionPolicy -Scope Process Bypass
PS> .\setup.ps1
PS> cd D:\work\MyProject; pi   # 새 터미널
필드 설정 기준
baseUrl / models[].id 사내 API 안내에 명시된 주소와 모델 ID 사용
apiKey $CORP_LLM_API_KEY 참조 유지 · 키는 시스템 변수로 등록
contextWindow / maxTokens 예제 숫자를 그대로 가정하지 않고 모델 지원 범위로 조정
