# plan

**구현하지 않고 계획만 설명한다.** 이 스킬이 켜진 동안 파일을 수정하지 않는다.

## 금지

- `edit`, `write`를 호출하지 않는다.
- 파일을 바꾸거나 만드는 `powershell` 명령(리다이렉션, `sd`, `Set-Content`, `git commit`, 빌드 산출물 생성 등)을 실행하지 않는다.
- "이렇게 고치겠다"는 코드를 파일에 적용하지 않는다. 필요한 코드는 답변 안의 짧은 조각으로만 보여 준다.

## 허용

- `read`, `grep`, `find`, `ls`, `find_symbol`, `lsp_diagnostics`와 읽기 전용 `powershell` 명령(`git log`, `git diff`, `rg`, `fd`)으로 현재 코드를 조사한다.
- 추측하지 말고 실제로 읽은 파일·함수·줄 번호를 근거로 쓴다.

## 순서

1. 요청을 한 문장으로 다시 적는다. 모호해서 계획이 갈라지면 `/skill:align`을 권하고 멈춘다.
2. 관련 코드를 읽어 현재 동작과 영향받는 지점을 찾는다. 정의·사용처·테스트를 함께 확인한다.
3. 아래 형식으로 답한다.

## 답변 형식

- **목표**: 한두 문장.
- **현재 상태**: 읽은 근거(`경로:줄`)와 함께 지금 어떻게 동작하는지.
- **변경 계획**: 파일별로 무엇을 어떻게 바꾸는지. 순서가 있으면 번호를 붙인다.
- **대안과 선택 이유**: 실제로 고민할 만한 대안이 있을 때만. 추천 하나를 먼저 쓴다.
- **위험·영향 범위**: 깨질 수 있는 호출자, 인코딩·줄바꿈, 빌드 설정.
- **검증 방법**: 실행할 빌드·테스트·진단. 실행하지 않았으면 실행하지 않았다고 쓴다.
- **확인이 필요한 점**: 사용자가 정해야 하는 것만.

끝에 "승인하면 구현하겠다"고 적고 멈춘다. 사용자가 명시적으로 구현을 요청하기 전에는 시작하지 않는다.
